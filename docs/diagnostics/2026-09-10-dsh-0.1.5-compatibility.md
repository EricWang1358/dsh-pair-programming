# DSH 0.1.5 compatibility check (2026-09-10)

The installed host and SDK packages are **0.1.5-rc.1**, with Cordis 4.0.2.
This is not evidence for a separately released final 0.1.5 package.

## Confirmed regression and fix

DSH commands now normalize `input.attachments` and use it in `CommandRuntime.execute`
to admit uploaded content. The old `input.images` field is discarded. Previously,
`/pair` registered successfully but rejected attached screenshots before its handler.
The plugin now declares both fields, retaining the old declaration for older hosts,
and calls uploaded content attachments in its acknowledgments (files are also admitted).

The host-contract regression mounts native CommandRuntime and LocalAttachmentStore,
persists a valid PNG in a temporary home, and confirms Captain receives its durable
attachment reference. Invalid base64 is rejected before a follow-up is created.
The Agent follow-up receiver and lifecycle session remain test doubles; no model runs.

## Other interfaces

Final targeted run: **269 passed, 0 failed across 12 suites** (events, command,
host-contract, members, isolated-members, settings-host, lifecycle-output, panel,
wake, dual-lifecycle, integration, parallel-tasks). Git subprocess tests required
a sandbox exception; the initial sandbox EPERM was an environment failure.

Runtime imports and startup wiring pass (26 tools, /pair, gesture and scheduler hooks).
Native registry checks cover tools, command metadata, skills and declared service APIs.
Targeted suites also cover settings, lossless pair_status output, panel transport,
member replacement, isolated member routing and dual Driver lifecycle.
Startup uses a mock context; it is not a complete production host boot.

The unknown session-event guard remains necessary. Its logged-once test previously
assumed other suites had already populated the dedupe cache; it now separates those
logs from its own probe. No event persistence behavior was changed.

## Operational scope

No paid model call, live team mutation, npm publication or host restart was performed.
Restart the DSH host to load changed ESM code from the linked local plugin.
Older SDK versions were not reinstalled or rerun during this check.

## Follow-up: production panel route failure

The initial check missed the WebServer ownership boundary. The live host at port
3080 returned HTTP 405 for POST /pair-runtime/snapshot; the frontend fallback
returns that status when no route exists. This happens before board reading.
With native WebServer and Connection services, legacy rpc.handle reproduces
`cannot get property "webServer" without inject`: its registration reaches through
the Connection owner scope. Merely adding webServer to the panel injection did not
fix the native-service case, although the old plain-object webServer fixture passed.

The panel now registers exact /api/pair-runtime/snapshot and /watch Fetch routes
through connection.fetch.register. The existing authenticated /api carrier owns HTTP
and authentication. No SDK code or live team is changed. Client fallback is limited
to HTTP 404/405 for older hosts, and error UI no longer says to create a team.

Regression checks include actual WebServer route dispatch and panel-only disposal,
late server availability, authentication and origin rejection, invalid envelopes,
watch cancellation, reconnect fallback and error rendering. The existing production
host has not been restarted while its agents are working; post-restart verification
of that particular team's live panel remains outstanding.
