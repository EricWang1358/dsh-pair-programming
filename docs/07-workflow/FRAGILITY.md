## F1 ✅ 已修复：判决可被声明缺陷伪造

**曾经的形状。** `verify_plan` 被文档描述成散文（"How the change will be verified"），却被 `pair_verify(stage="checkpoint")` 当成 shell 命令逐字执行。散文 → 非零退出 → `verdict: 'reject'`。

**为什么它比"卡住"更严重。** 这个协议的全部主张是"判决是一次重跑，不是一次表态"——`computeVerdict` 存在的理由就是让人无法声称通过。伪 REJECT 从另一侧击穿同一主张：它**用声明缺陷制造了一个机器判决**，计入 `stats.reject`、烧掉循环拒绝预算、把圈退出 GO、并向 Driver 投递一份关于其代码的结构化反馈——而代码从来不是问题。**可能因产品无关原因出错的证据，不是证据。**

**修复。** `commandShapeError` 在两处拒绝：`pair_propose`（错误发生的地方）与 checkpoint 执行前（旧构建遗留的圈）。执行前那次拒绝的是**调用**，不是产出一个判决——圈保住步骤与预算。

**留下的类。** 见 F2。

## F2 ✅ 已闭环：声明字段与执行语义的隐性契约

**形状。** 协议里有四个字段"被当作某种东西执行"，而它们的类型只是 `string`。写下字符串的时刻与它被交给 shell 的时刻之间隔着若干协议步骤，中间没有类型可言。F1 只补了其中一格；0.13.2 补齐了其余三格。

| 字段 | 被谁执行 | 声明点校验 | 执行前校验 |
|---|---|---|---|
| `proposal.verify_plan` | checkpoint 验证 | ✅ `pair_propose` | ✅ verify |
| `oracle.cmd` | 每次 final 判决 | ✅ `pair_oracle`（RED 运行**之前**） | ✅ `redProblem` |
| `dodCommand` | 门禁 | ✅ `settingsValueError` | — |
| `green_build_command` | `pair_stop` | ✅ stop 参数校验 | — |

**`oracle.cmd` 是最深的一格，值得单独说。** 冻结门禁要求命令**失败**——这是 RED 的定义。所以它天然**奖励跑不起来的命令**：

- 散文 → 失败 → 通过 RED 检查 → 封进契约 → 此后每次判决都"失败"
- 打错的 `npn test` → 同上

两者在看板上都读作"实现始终不达标"，而真实原因（三个字符）完全不可见，因为**失败正是 oracle 该做的事**。

形状检查**抓不到** `npn test`：那是一条完全合法的命令行。所以补了第二层——`notRunnableEvidence` 看的是**它怎么失败的**：not-found 退出码（127 / 9009）、spawn 失败、或 shell 自己的 not-found 文案。这一层被接进 `redProblem`，所以跑不起来的命令**无法完成冻结**。

**保守设计**：退出码判据在先，文本判据只覆盖那些用 exit 1 报 not-found 的 shell。一个自身输出里含 "command not found" 的测试套件，仍然以它自己的退出码为准。

**留下的边缘**（可接受，已记）：一条命令**存在**但语义错误（跑了错的套件），仍然无法被机械分辨——那需要人读。

## F2b 🟠 判据本身是启发式

**形状。** `commandShapeError` 用的是形状启发式（多行 / 列表符号 / requirement 词 / 句读）。它刻意**宽松**：拒绝合法命令会挡住真实工作，而放过散文只是把错误推迟到 shell。

**风险方向明确**：它会**漏**（某些散文长得像命令），不会**误杀**（合法命令被拒）。漏掉的那部分由 `notRunnableEvidence` 在运行时兜住——散文的首词几乎必然 not-found。

**不要做的事**：不要用 LLM 判断"这是不是命令"。那会把脆弱点从字段搬到判断器上，且判断器不可重放——而这整套机制的价值就在于**确定性**。

## F3 🟠 归因只到 workspace + 时间窗，不到席位

**形状。** CE 加载账本、写车道拒签的归因单位是"工作区 + 时间窗"。因为 `SkillProvider.get` 只收 `{cwd, signal}`，没有调用者身份，而注册表的 scope 分层绑定 agent preset 常驻组合，我们用 `startContinuable` 派生的成员拿不到独立层。

**后果。** 同一工作区并行多任务时，一次**合法**的写车道加载会拒掉**无关卡片**的凭证。solo 模式下 implementer 就是 captain，这个面更宽。

**为什么不能靠加测试解决。** 这是宿主契约的形状，不是我们的实现缺陷。测试只能钉住"我们按窗口归因"，钉不出席位身份。

**解决方案**

1. **短期（已做）**：拒签文案明说归因方式、明说误拒边缘、给三条可执行出口、明说没有豁免开关。
2. **中期**：把窗口从"任务最早循环"收窄到"当前循环 openedAt"。窗口越短误拒越少，代价是跨循环的违规可能漏网——这是个可以量化的权衡，建议先用账本数据估算两种窗口下的命中/误拒比。
3. **长期**：等宿主给 `SkillProvider` 传入调用者 scope。这是上游能力，不是我们能自建的——**不要用启发式伪造席位身份**，那会把一个诚实的粗粒度换成一个不诚实的细粒度。

## F4 🟠 角色轮换整体停用：能力缺口而非缺陷

**形状。** `pair_rotate` 无条件抛错。成员能力在 spawn 时绑定，轮换会让新 Driver 缺写权、旧 Driver 留写权——I1 两头倒挂。

**为什么列在这里。** 它本身是诚实的（拒绝文案自陈原因与缓解），但它让**另一条已记录的防线不可达**：`toolFilter` 在轮换时的 P1 处理永远走不到。账本若把它记成"已缓解"会误导后人。

**解决方案**

1. **账本层（立即）**：把"不可达"与"已修"分开记。它们在 M2' 落地那天会变成完全不同的两件事。
2. **实现层（M2'）**：写权动态 guard。真正的形状是把 I1 从"spawn 时的 toolFilter"搬到"每次写调用时查看板"——`board-guard.js` 已经证明这条路可行（它就在 `tools/pre-execute` 上按看板判定）。轮换随之变成一次看板写入，不再需要重建席位。
3. **前置债已部分清偿**：retired 语义基建（`markMemberRetired` / `installRetiredInboxGuard`）已落地，账本里"零消费者"的表述作废。

## F5 🟠 会话事件面永久沉默，且注释曾诱导致命改动

**形状。** 本插件发出的 6 种 `pair/*` 事件全部被丢弃。这是**正确的**：`append()` 不校验类型，但 `dsh-session-persistence.assertEventsSupported` 会对未知类型抛 `SessionFormatUnsupportedError` **拒绝解释整个 log**，而 `ignorable` 逃生口 `append()` 无从设置。

**脆弱在哪。** 不在代码，在**它看起来像 bug**。任何"顺手修好"的改动都会用一个没人拥有的 UI 面板换掉会话恢复能力。0.12.4 前的模块注释还在宣传那个不可能存在的时间线。

**解决方案**

1. **已做**：注释改成陈述机制链，`events.test.mjs` 把宿主事实钉死——将来宿主真开放插件词汇时断言会红，改动变成有意识的决定。
2. **待做**：这类"看起来像死代码的承重代码"应该有统一标记。建议在代码里用固定标签（如 `LOAD-BEARING:`）+ 一条测试，让 grep 能一次列全。目前只有这一处，但同类会再出现。

## F6 🟠 宿主契约的验证覆盖仍有三个洞

**形状。** `llm` / `agents` / `subagents` 没有独立挂载方式（需要活模型、session store、子代理驱动），所以它们的**行为**只有实跑覆盖。

**已收窄（0.13.5）**：`settings` 从这一类里移出——`settings-host.test.mjs` 挂真实 file provider 跑完整往返（组合值落地、写入进 user 层且 base 保留、插件校验器在宿主写路径内生效、两个命名空间共存）。它带 `finally` 里的 fork dispose：provider 有文件 watcher，不释放会把 runner 挂住——**那正是促成这个文件的那个一次性探针跑了几小时没人发现的原因**。现在真正剩下的是 `llm` / `agents` / `subagents` 三个。

**已经付过的代价。** 幻影 API `ctx.subagents.followup` 从这个洞里出去，导致成员唤醒长期静默失败——而症状被误记为协议设计问题（"看板静默"）。CE provider 缺 `provider` 字段从同一类洞出去，CE 目录死了四个版本。

**解决方案**

1. **已做**：方法**存在性**已静态钉住，且 0.13.3 起覆盖**全部 8 个宿主服务**（`subagents` / `skills` / `tools` / `commands` / `settings` / `systemPrompt` / `llm` / `agents`）与 Agent handle 面。守卫自己断言"确实扫到了东西"（≥10 处调用），所以它不会因为正则没匹配而空绿。这拦得住整个"幻影 API"家族。
2. **待做（性价比中）**：请求**形状**校验。宿主的 `.d.ts` 有 `SubagentPromptRequest` / `ContinuableStartSpec` 这样的接口，可以从 `.d.ts` 抽必填字段名，断言我们构造的对象包含它们。不完美（不校验类型），但能拦住"少传一个必填字段"。
3. **不建议**：为了可测性给这三个服务写 mock 实现。mock 会变成第四个真相源，和 stub 的问题一模一样。

## F7 ✅ 已闭环：账本与代码之间没有机判连接

**曾经的形状。** M 表、AGENTS.md、CHANGELOG 都是散文。判决被推翻时没有 supersession 边，读者顺编号找条目、不会先读最新一版——所以一条被推翻的判决，读到它的人会当它有效。已经出现过一次有破坏力的实例：M11' 的旧修法（"删 appendPairEvent 死路径"／"向 SDK 注册 pair 事件命名空间"）在 0.12.4 反向判决后仍是可执行指令，照做会用一个不存在的 UI 面板换掉会话恢复能力。

**修复三层。**

1. **约定成文**（AGENTS.md §2 头）：每条 M 项带 `状态 / 证据 / 推翻者`；**缺省视为"未核"而不是"开放"**；证据记 `file:line` 指针不记结论——指针会漂移，漂移时 grep 一下就知道，结论只会变假；编号只增不改，空号永久保留。
2. **推翻标记写在被推翻的那一行上**。M11' 的条目现在自带 ⛔、反向判决的版本号、四条机制链（append 不校验类型 → 已知类型集是读路径且下游插件事件永不在内 → assertEventsSupported 抛错拒绝解释整个 log → ignorable 逃生口 append 无从设置）、以及代价对比。带 ⛔ 的行是**禁止执行**，不是低优先级。
3. **机判看守**（`tests/ledger.test.mjs`）。刻意窄：只钉**做错了代价大于一次 grep** 的那几条——⛔ 必须仍是 ⛔；声称"开放"的能力必须仍不在代码里（`pair_rotate` 仍拒绝、`typecheck.mjs` 仍无 EPERM 处理）；声称"已落地"的必须仍在（gate 亲跑 dodCommand、退休名单有真实消费者、幻影 API 已从唤醒路径消失）。

**为什么不钉全部。** 把每条账本行绑到代码会让账本无法维护，也会让这套测试变成第二个真相源——那正是 stub 的问题。目标只是：**少数会造成伤害的行，不能悄悄烂掉。**

**顺带清掉的过时行**：M7'（已落地，gate 亲跑）、M8'（0.5.0 已落地，裁决 v2 的"无限期挂账"就地标注）、M2' 地基实况的"retired 零消费者"（已被 `installRetiredInboxGuard` 推翻，就地标 ⚠️ 并保留仍成立的那一半：`status='removed'` 的写入语义仍未定义）。

## F8 🟠 显示标记用模块级可变状态，跨上下文共享

**形状。** `nav-model.js` 的 `installedScope` / `lastStatus` / `fallbackState` 与 `members.js` 的 `navRouteFallbackDetail` 都是**模块级**可变量。理由是真实的：调度器与生命周期在**看不到 settings 服务**的上下文里探测到配额死亡，标记必须能通过普通 import 写入。

**代价。** 同一进程里两个插件实例会共享这些标记——A 部署的配额回退会在 B 部署的卡片上显形。`wake.js` 对同类问题用的是 `WeakMap` keyed by ctx，正是为了避免这个。

**为什么现在不改。** 单进程多实例目前不是真实部署形态，而改造要把标记通道从"普通 import"换成"按 ctx 查找"，会波及调度器与生命周期两条错误路径——那是这一轮刚修好的地方。

**触发条件（写下来，免得靠记忆）**：一旦出现同进程多组合，或标记从"显示"升级为"任何东西据以判决"，就必须改成 `WeakMap` keyed by ctx。**它现在是显示，所以可以共享；它一旦参与判决，就不能。**

## F9 ✅ 已闭环：配置字段可以在链路中途蒸发

**形状。** 一个字段要真正生效，必须同时出现在四处：`Config`（可在 YAML 声明）→ `resolveConfig`（组合值存活）→ `settingsEntry`（成为设置基线层）→ `toRuntimeSettings`（回到运行时）。少任何一环都会**静默**失效，而且失效方式各不相同：少了 `resolveConfig`，YAML 值被丢弃；少了 `settingsEntry`，卡片显示 schema 默认值且"恢复"回到空；少了 `toRuntimeSettings`，UI 显示一个没人读的旋钮。

`lib/defaults.js` 的头注释就是为这件事写的——然后 `navigatorModel` 还是在 0.13.0 掉进去了。散文注释挡不住这个。

**修复。** `settings.test.mjs` 现在对四段链路做交叉断言，并且验证**值**而不只是键。新增字段在补齐全链之前无法通过测试。`dod` 是唯一的显式例外（index.js 自己解析），在断言里点名豁免。
