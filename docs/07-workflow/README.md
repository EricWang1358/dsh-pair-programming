# 07-workflow — 功能工作流、时序与架构脆弱点

三份文档，三个切面，同一套事实：

| 文件 | 组织方式 | 回答的问题 |
|---|---|---|
| [WORKFLOW.md](WORKFLOW.md) | 按**能力**（Epic → User Story → Sub-feature） | 这个插件有哪些能力？每条**靠什么强制**？失效时看板长什么样？ |
| [LIFECYCLE.md](LIFECYCLE.md) | 按**时间**（阶段 0 → 7） | 一个需求从进门到签发回执，每一步谁在动、哪个门在此刻会拒绝你？ |
| [FRAGILITY.md](FRAGILITY.md) | 按**风险** | 哪些机制可能在不报错的情况下失效？怎么办？ |

## 共用判据

> **一项能力如果没有"机判点"，它就不是不变量，只是习惯。**

WORKFLOW 用空白列显式暴露这件事；FRAGILITY 收录那些机判点本身可能静默失效的地方；
LIFECYCLE 把两者按执行顺序串起来，让"这一步现在会不会拒绝我"可以直接查到。

## 强制强度的偏好顺序

**能物理隔离的不用机判，能机判的不用记账，能记账的不用提示词。**

| 强度 | 形态 | 例 |
|---|---|---|
| 物理 | 席位根本没有那个工具 | SPEC 无 reader/shell |
| 机判 | 工具调用时计算后拒绝 | oracle 摘要漂移 = 自动 REJECT |
| 记账 | 不阻断，但落成不可否认的记录 | CE 加载账本、披露轨 |
